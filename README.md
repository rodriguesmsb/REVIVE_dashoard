# REVIVE

An R Shiny dashboard for **Respiratory Viral Infection Vaccine Effectiveness in
Transplant Recipients**, using the sidebar, summary cards, and content cards from
the [Posit dashboard template](https://shiny.posit.co/py/templates/dashboard-tips/)
as a layout reference.

From the project root, run:

```r
shiny::runApp(".")
```

Required R packages: `shiny`, `bslib`, `DT`, `plotly`, `jsonlite`, `htmltools`,
`readr`, and `dplyr`.
At startup, `R/RDS_generation.R` reads `data/Patients_characterisitics.csv`,
applies `harmonize_patients()`, and saves the harmonized CSV and RDS under
`data/preprocessed/`. The dashboard uses the returned data directly.
`R/json_generation.R` reads CSV files directly under `data/` whose names contain
`infection` or `vaccin` (case insensitive) and writes
`data/preprocessed/longitudinal_events.json`. The six type/date pairs are named
explicitly, and labels follow the codes in `ref/Revive_dictionary.pdf`.
Dates use the exports' `YYYY-MM-DD` format. IDs remain text, blank slots are
omitted, and repeated reports are retained. Each patient has separate infection
and vaccination arrays, including empty arrays for patients without reports.
Restart the app after updating the source exports; all derived files are rebuilt.

The current `Flu_infections.csv` is an unreadable, 8-byte file. It is explicitly
excluded through `skip_files` in `global.R`, with a warning at startup. Replace
it with a valid CSV and remove that exclusion to include its reports.

`global.R`, `ui.R`, and `server.R` coordinate the application. The first module,
`R/mod_dashboard.R`, owns the filters, patient count, table, CSV download, and
swimmer plot. `R/RDS_generation.R` prepares the dashboard inputs from the explicit
columns produced by `R/REVIVE_harmonization.R` and event histories generated by
`R/json_generation.R`.
`R/helpers_dashboard.R` contains only filter, table, and plotting functions;
the Arctic reflection palette is defined in `www/custom.css`.

Filters apply together at the patient level. A category matches any selection
or report for that patient. The full age range means **All**, including missing
ages; a narrower range includes only known ages within that range. Reset restores
all seven filters. Study group appears immediately after Patient ID in the table
and CSV export. SOTR describes organs from the **most recent transplant**,
using the harmonized organ indicators. The table and CSV include every matching patient;
the CSV includes all matching rows, regardless of the table's current page.

Export CSV opens a window with a searchable selection of additional variables
from the harmonized patient characteristics. The displayed columns are always
included first; selected variables are appended in selection order and matched
by patient ID. Leaving the selection empty exports only the displayed columns.
The available extra variables are defined explicitly in `revive_export_columns()`
in `R/helpers_dashboard.R`, currently `ig_plasma` and `ig_plasma_3mo`. Edit that
list and restart the app to change both the selector and allowed download fields.
Variable search runs on the server, and extra data
columns are assembled only when downloading.

The swimmer plot shows all dated events for matching patients. Infection uses
red (`#a00000`) circles and vaccination uses teal (`#298c8c`) squares. Patients
without dated events remain in the count, table, and export. Lines connect first
and last recorded events and do not imply observed follow-up time. Multiple
reports at the same coordinates can overlap. The chart scrolls vertically and
supports hover details, zoom, and PNG download.

Run dashboard checks from the project root:

```sh
Rscript tests/test_dashboard.R
```
